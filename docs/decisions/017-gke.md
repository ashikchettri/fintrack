# ADR 017 — GKE on Google Cloud (Terraform foundation)

**Status:** Accepted · 2026-07-25

## Context

The Helm chart (ADR 016) deploys FinTrack to any cluster; the next milestone is a real cloud target — GKE. That needs cloud infrastructure (a cluster, an image registry, a managed database, secret storage) and an identity model that never ships long-lived keys. This ADR sets that foundation as **Terraform** under `infra/gke/terraform`, so the cloud is codified, reviewable and reproducible rather than click-ops. Provisioning is run by the owner against a **dedicated** project (it incurs cost); nothing here is applied automatically.

## Decision

1. **Terraform, not click-ops.** The whole cloud footprint is declared in `infra/gke/terraform` (validated with `tofu/terraform validate`). `project_id` is a required variable with no default — a guard against provisioning into a shared or unrelated project (the machine's active gcloud project is someone else's prod).

2. **GKE Autopilot.** Google manages nodes, bin-packing and upgrades; **Workload Identity is on by default**, which is the whole point of the identity model below. `REGULAR` release channel.

3. **Managed data + secrets.** **Cloud SQL for PostgreSQL 17** replaces the in-cluster StatefulSet (the chart's `postgres.enabled=false`), reached via the **Cloud SQL Auth Proxy** (IAM-authenticated — no authorized networks). The app DB password is generated by Terraform and written only to **Secret Manager**, alongside empty secrets for the Anthropic key and the JWT signing key (versions added out-of-band). **Artifact Registry** holds the images.

4. **Keyless identity end to end.**
   - *App → Google APIs:* an app GSA (`fintrack-app`) with `cloudsql.client` + `secretmanager.secretAccessor` + `artifactregistry.reader`, bound to the in-cluster KSA via Workload Identity — pods get tokens, never keys.
   - *GitHub Actions → Google:* **Workload Identity Federation** (OIDC) — a pool/provider scoped to this repo lets workflows impersonate a deployer GSA (`artifactregistry.writer` + `container.developer`). No service-account JSON keys anywhere.

## Consequences

- **Positive:** the cloud is code (diffable, reproducible, destroyable); zero static credentials (Workload Identity + WIF); managed Postgres/registry/secrets remove operational load; the `project_id` guard prevents a costly mistake.
- **Negative / cost:** running infra costs money (Autopilot has a cluster fee; Cloud SQL runs 24/7) — tear down when idle; Terraform state is local for now (a GCS backend is a follow-up before any team use); a public-IP Cloud SQL (proxy-gated) is simpler than private IP + VPC peering but worth hardening later.
- **Next (separate PRs, need the infra to exist to test):** a **Cloud SQL Auth Proxy sidecar** + Secret Manager wiring (CSI driver / External Secrets) in the Helm chart, a concrete `values-gke.yaml`, a **GCE Ingress + managed TLS cert**, and a **`deploy-gke.yml`** workflow (WIF → build/scan/push to Artifact Registry → `helm upgrade`).
